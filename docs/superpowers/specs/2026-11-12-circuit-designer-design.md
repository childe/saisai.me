# 电路实验室（circuit）设计

日期：2026-11-12
状态：待用户批准

## 1. 这是什么、为什么做

「赛赛的工具箱」新增一个模块：**电路实验室**。孩子在 iPad 上用手指拖元件、连导线，自己搭电路图，搭好立即看到效果：灯亮、LED 发光、风扇转、蜂鸣器响、电表读数、短路报警、保险丝熔断。

用户原话：「可以自己设计电路图，并展示效果」「可以拖动搭建，可以串联并联，可以有灯光，二极管」。

做得好的标准：孩子能自己摸索出「串联变暗、并联不变」「LED 有方向」「电阻保护 LED」「楼梯灯怎么接」这类规律，靠的是**按真实物理算出来的效果**，而不是预先写死的动画。

## 2. 目标

- 自由搭建画布：拖元件、连导线、调参数、旋转、删除、撤销、清空。
- 全部元件这一版都做（见第 5 节）。
- 效果按真实物理计算（用户明确选择，不做「通了就亮」的简化逻辑）。
- 10 个小任务，自动判定完成（见第 7 节）。
- 元件两种画法：实物卡通 / 标准电路符号，一键切换（用户选定）。
- 目标设备 iPad Safari，横屏，手指操作（用户选定）。

## 3. 非目标

- **不保存**电路（用户明确：先不存）。刷新页面即清空。
- 不做交流电、电容、电感、晶体管、集成电路。
- 不做账号、分享链接、云端任何东西。
- 不做手机竖屏适配（能打开即可，不保证好用）。

## 4. 反目标（做到了也算失败）

- 物理结果明显违反常识：串联两个灯和一个灯一样亮；LED 反接也亮；电压表串进电路里灯还正常亮。
- 手指在 iPad 上连不准导线、拖不动元件、误触频繁。
- 求解出错时页面卡死、白屏或出现 NaN 读数。
- 页面需要构建步骤或联网才能运行。

## 5. 元件与物理模型

数值是**建造者可以调**的默认值，目标是效果在孩子眼里合理、彼此一致。

| 元件 | 端点 | 模型 | 可调参数（点选后面板） | 效果表现 |
|---|---|---|---|---|
| 电池 | +、− | 理想电压源 1.5V × 节数，串内阻 0.1Ω/节 | 节数 1–4 | 短路（电流超过约 3A）时电池发红、出现「短路啦！」气泡 |
| 小灯泡 | 2 | 电阻约 10Ω，额定约 3V/0.3A | 无 | 光晕大小/亮度 ∝ 实际功率 / 额定功率；超过额定功率约 2 倍持续即烧断（灯丝断，变灰），点「换新」恢复 |
| 开关（单刀单掷） | 2 | 闭合 ≈ 0Ω，断开 = 开路 | 点一下切换 | 拨片动画 |
| 导线 | 2 | ≈ 0Ω（数值上用极小电阻）。**不是元件栏里的元件**：只能从端点拖到端点画出来，数量不限（设计者决定） | 无 | 有电流时小点沿电流方向流动，速度随电流大小 |
| LED | 阳极、阴极 | 二极管：导通电压约 2V，指数或分段线性模型 | 颜色（红/绿/蓝/黄） | 正向导通才亮；电流超过约 30mA 烧坏：冒烟→变黑，点「换新」恢复 |
| 电阻 | 2 | 定值电阻 | 阻值档位：10/47/100/220/470/1kΩ | 实物画法用色环表示阻值 |
| 电动机/小风扇 | 2 | 电阻约 5Ω | 无 | 转速 ∝ 电压，反接反转 |
| 蜂鸣器 | +、− | 电阻约 50Ω，有极性 | 无 | 通电真实发声（Web Audio），音量随电流；全局静音按钮 |
| 滑动变阻器 | 3（两端 + 滑片） | 两段电阻，总值 0–50Ω | 拖滑块 | 滑块连续拖动时电路实时更新 |
| 单刀双掷开关 | 3（公共 + 两触点） | 公共端接其中一个触点 | 点一下切换 | 拨片动画 |
| 电流表 | +、− | 内阻约 0.01Ω | 无 | 表盘显示读数（A），反接显示负值/指针反偏 |
| 电压表 | +、− | 内阻约 10MΩ | 无 | 表盘显示读数（V） |
| 保险丝 | 2 | ≈ 0Ω，额定电流 | 额定：0.5A / 1A / 2A | 超过额定即熔断，点「换新」恢复 |

### 求解

- 每次电路结构或参数变化后，重新求解整张电路：修正节点分析法（MNA），线性元件直接解，LED 用牛顿迭代。
- 烧断/熔断是状态变化：元件变成开路后需要再解一次，直到状态稳定（设迭代上限，防止来回振荡）。
- **损坏的时间规则**（设计者决定）：保险丝熔断、LED 烧坏是瞬时判定；灯泡过载和电池短路要持续约 0.5–1 秒才判定（灯泡烧断、电池报警）。所以求解器外面要有一个定时循环累计过载时长，这样拖变阻器滑块时扫过高功率点不会立刻烧灯。
- **孤立部分的处理**：按导线和元件把端点分成电气连通分量，每个分量单独求解。
  - 断开的开关、烧断的灯丝、熔断的保险丝只是「这条支路开路」，不把所在分量整体排除；两端节点照常有电位。例：电池、灯泡、开关串联，开关断开后灯灭，电压表跨在开关两端仍读到约电池电压。
  - 分量里没有电池（无源孤立部分）时，所有节点电位记为 0、电流为 0，不报错。
  - 每个分量各自选一个参考点，避免浮动节点让矩阵奇异。
- **数值失败**（奇异矩阵、迭代不收敛）时：本次结果标记为无效。界面显示「暂时无法计算」，电表读数显示「--」，停止电流小点动画；任务判定和过载计时都暂停；上一次结果只能作为变灰的画面残影，不当作当前读数。任何时候不显示 NaN，不卡死。
- **三个接口分开**（都是纯函数，放 `circuit/lib/`，可以在 Node 里单测）：
  1. `solve(电路)` → 各元件电压、电流，加 `ok`（是否有效）和输入电路的版本号。不改元件状态。
  2. `advance(损坏状态, 求解结果, 经过时间)` → 新损坏状态（熔断、烧坏、过载累计时长）。只接受 `ok` 为真且版本号与当前电路一致的结果。
  3. 任务判定器：在电路的独立副本上改开关状态、调用 `solve`，只读结果，不调用 `advance`，不改真实电路。

## 6. 界面（用户选定布局 A）

iPad 横屏：

```
┌──────────────────────────────────────────────────────────┐
│ ⚡ 电路实验室  [自由搭建][小任务]  [🧸实物|⊗符号] [🔇] [↶撤销][🗑清空] │
├────────┬─────────────────────────────────────────────────┤
│ 元件栏 │              点阵背景画布                       │
│ (竖排) │                                   ┌参数面板┐   │
│        │                                   └────────┘   │
└────────┴─────────────────────────────────────────────────┘
```

- **左侧元件栏**竖排；元件多于一屏时可上下滑动。
- **放置**：从元件栏按住拖到画布松手。元件吸附网格。
- **连线**：从元件端点按住拖到另一个端点松手。端点触控范围要比画出来的大（手指友好）。一个端点可以连多根导线，作为汇合点。导线画成直角折线（建造者决定走线细节）。
- **选中**：点一下元件，弹出参数面板（参数、旋转 90°、删除、烧坏后的「换新」）。
- **开关的两种点击**（单刀单掷、单刀双掷相同）：开关上画一个明显的拨片按钮。点拨片 = 切换通断，不弹面板；点开关的其他部分 = 选中，弹参数面板（面板里也有「切换」按钮）。拨片的触控区与元件其余触控区不重叠，各自不小于 44pt。验收：两种开关都能切换、选中、旋转、删除。
- **移动**：拖动已放置的元件，连着的导线跟着走。
- **删除导线**：点选导线后删除。
- **撤销**：至少能撤销放置、移动、连线、删除、参数修改。
- **清空**：需二次确认（页面内的确认，不用浏览器弹窗）。
- **画法切换**：同一张电路在实物卡通和标准电路符号两种画法之间切换，位置和连线不变。
- **静音**：控制蜂鸣器声音。

整体视觉沿用工具箱首页的暖色调（`#fff8ec` 底色等）。

## 7. 小任务

顶部一行显示目标；左侧元件栏只出现这一关给的元件和数量；系统按求解结果自动判定，完成后显示通过提示和「下一关」。不锁关，任务列表可以随意挑。

| # | 名称 | 目标 | 给的元件（建议） | 判定（建议） |
|---|---|---|---|---|
| 1 | 点亮一盏灯 | 让灯亮起来 | 电池×1、灯泡×1 | 灯泡亮 |
| 2 | 加个开关 | 用开关控制灯 | 电池、灯泡、开关 | 开关闭合时灯亮、断开时灯灭（判定器分别模拟开关两种状态） |
| 3 | 串联和并联 | 两种接法都试，并比较亮度 | 电池、灯泡×2 | 两灯都亮时记下每灯功率；第一次两灯都亮后提示「试试另一种接法，亮度有什么不同？」；之后再次两灯都亮、且每灯功率与记下的值相差 2 倍以上（换了接法）才通过 |
| 4 | 一个亮一个灭 | 一个开关只控制其中一个灯 | 电池、灯泡×2、开关×1 | 开关断开：一亮一灭；闭合：两个都亮 |
| 5 | 让 LED 亮起来 | 点亮 LED 且不烧坏 | 电池×2、LED、电阻 | LED 亮且未烧坏 |
| 6 | 调光台灯 | 用变阻器调灯的亮度 | 电池、灯泡、滑动变阻器 | 判定器在副本上把滑块放到两端各解一次：两次灯泡功率都 > 0（没有被断开），且大功率 ≥ 小功率 × 2（1 节电池、变阻器 0–50Ω 时约 30 倍，留足余量） |
| 7 | 让风扇反转 | 让风扇反着转 | 电池、电机（预先放好、正转） | 电机反转 |
| 8 | 楼梯灯 | 楼上楼下都能开关同一盏灯 | 电池、灯泡、单刀双掷开关×2 | 任一开关切换都改变灯的状态（判定器枚举 4 种组合） |
| 9 | 量一量 | 测出灯泡的电流和电压 | 电池、灯泡、电流表、电压表 | 电流表与灯串联、电压表与灯并联，读数非零且灯亮 |
| 10 | 保险丝救场 | 用保险丝保护短路的电池 | 预置「电池被导线直接短接」的电路（电池发红报警），给保险丝×1 | 熔断前最后一次有效结果里，流过保险丝的电流与电池电流相等（保险丝在电池短路回路上）且超过 3A；熔断后电池电流 < 3A |

判定用语：
- 「灯亮」= 灯泡未烧断且实际功率 ≥ 额定功率的 5%；「LED 亮」= 未烧坏且正向电流 ≥ 1mA。
- 所有判定只用 `ok` 为真的求解结果（见第 5 节）。

判定的具体实现（尤其 2、4、6、8 需要在副本上改开关或滑块）由建造者实现，原则是「按物理结果判定，不按接线拓扑死匹配」。

## 8. 技术约束（照现有模块）

- 放在仓库根目录新目录 `circuit/`，入口 `circuit/index.html`；首页 `index.html` 与 `README.md` 加入口。
- 纯静态：原生 HTML/CSS/JS ES 模块，无构建步骤、无 npm 运行时依赖、不联网。
- 渲染建议用 SVG（便于两种画法和触控命中），由建造者决定。
- 纯逻辑（求解器、元件模型、任务判定、撤销栈）放 `circuit/lib/`，用 Node 内置 `node:test` 写单测，放 `circuit/test/`，与 `pinyin/` 一致。
- 触控用 Pointer Events；禁用页面双指缩放与长按选字对画布的干扰。

## 9. 由我（设计者）决定、用户未明确表态的

- 搭好即实时生效，不设「运行」按钮。
- 电流流动小点动画，亮度用光晕表示。
- 蜂鸣器真实发声，配全局静音按钮。
- 10 个任务的具体内容（用户已看过清单并同意）。
- 第 5 节全部数值默认值。
- 目录名 `circuit/`、技术路线照 `pinyin/`。
- 损坏的时间规则：保险丝和 LED 瞬时损坏，灯泡和电池短路要持续约 0.5–1 秒。
- 导线只是连线，不限数量；任务 10 预置短路电路，孩子要把保险丝串进去。
- 自由搭建和小任务的画布互不影响。

## 10. 留给建造者

- 求解器数值细节（导线极小电阻取值、LED 模型形式、收敛判据）。
- 元件卡通与符号的具体美术。
- 导线走线算法、吸附网格尺寸。
- 画布是否支持平移/缩放（建议至少支持平移，画布固定大小也可接受）。
- 任务判定的具体实现方式。
