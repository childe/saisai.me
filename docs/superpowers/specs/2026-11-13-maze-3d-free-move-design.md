# 3D 迷宫连续移动与自由视角设计

## 意图

用户原话：「再修改一下，可以触摸操作，视角可以斜着，不要一直是90度转向，转向与按键的时候是连续，不要一下子转90度，不要一下子走到下个路口。只要迷宫生成和2d那个是一样的，其他操作可以是不一样的。怎么更方便操作，怎么让视觉效果更好怎么来。」

现状（`maze-3d/main.js`）：移动是离散的——按一次方向键，小人沿格子走到下一个路口；第一人称下左右键原地转 90°；跟随视角相机固定朝北、不可调。触屏只有四个方向按钮。

本次把操作改成现代 3D 游戏的手感：按住就一直走、松开就停，转向是连续角度，视角可以任意斜着看；触屏用虚拟摇杆加拖动转视角。迷宫生成保持与 2D 完全一致（已有测试锁定，不动）。

## 目标

### 移动

- 小人位置是连续坐标 `(x, z)`（世界单位，1 格 = 1），不再吸附到格子中心。
- 速度带加速 / 减速：最高速度 2.2 格/秒，从静止到满速约 0.15 秒，松开后约 0.1 秒停下。
- 碰撞：小人视为半径 `PLAYER_RADIUS = 0.28` 的圆，与每段墙（厚 0.1 的轴对齐矩形，按半径外扩）做碰撞，撞墙时沿墙滑动，不会卡住、不会穿墙。迷宫外边界（包括入口、出口两处开口）在碰撞上都视为封闭，小人不能走出迷宫。
- 每帧位移超过 0.1 时拆成多个子步计算，低帧率下也不会穿墙。
- 小人所在格 = `floor(z), floor(x)`。所在格进入右下角终点格时判定胜利（沿用现有恭喜提示层）。
- 渲染与碰撞共用尺寸常量：`PLAYER_RADIUS`、墙厚 `WALL_THICKNESS = 0.1`、墙长 `WALL_LENGTH = 1.1`、墙高 `WALL_HEIGHT = 0.8` 定义在 `movement.js`，`main.js` 引用这些常量，不再写死数字。小人模型（现有身体半径 0.3，瞳孔外伸到 0.36）整体缩放，使包括眼睛、瞳孔在内的水平最大外伸 ≤ `PLAYER_RADIUS`，贴墙时模型不嵌进墙里。通道净宽 0.9，直径 0.56 的小人在通道和转角都能通过（测试覆盖）。
- 小人模型平滑转向移动方向；移动时身体有轻微上下起伏（走路感），静止时不动。

### 视角

- 两种视角保留，用按钮切换：
  - **跟随视角（默认）**：相机绕小人旋转，有水平角 `yaw` 和俯角 `pitch`。默认 `pitch` 为 40°（斜着看），可在 15°–75° 之间调整；距离随迷雾视野半径变化（沿用现有 `followOffset` 的思路），并可在 0.7×–1.5× 之间缩放。相机平滑跟随。
  - **第一人称**：相机在小人眼睛高度，朝 `yaw` 方向，`pitch` 可在 −30°–30° 之间调整（默认 0°），右上角小地图保留。
- 相机若被墙挡住，把相机拉近到墙前，避免画面被墙填满。遮挡按三维判断：
  - 观察点 `target` = 小人位置上方 `TARGET_HEIGHT = 0.4` 处（相机 `lookAt` 这个点）。
  - 相机避障用三维包围盒表示墙：水平范围同碰撞矩形，高度 `0 – WALL_HEIGHT`；每个盒子向外扩 `CAMERA_MARGIN = 0.12`（大于近裁剪面 0.05 加近裁剪面在 50° 视场下的半宽，保证近裁剪面不切进墙里）。
  - 只有 `target → 相机` 这条三维线段穿过外扩后的包围盒时才拉近。水平投影跨过墙、但线段在该处高于 `WALL_HEIGHT + CAMERA_MARGIN` 时**不拉近**：斜着从墙顶上方看过去是正常视角。
  - 拉近与平滑的顺序：每帧先把「理想相机位置」（由 `yaw`、`pitch`、距离算出）平滑插值，再对**平滑后的方向**做避障，得到安全距离 `d_safe`。实际使用的距离 `d_cur` 若大于 `d_safe`，立即收到 `d_safe`（不插值）；若小于，按插值慢慢恢复，恢复后的值仍取 `min(插值结果, d_safe)`。因此每帧最终渲染用的相机位置都是安全的。
- 切换视角时保留 `yaw`，`pitch` 改为该视角的默认值。

### 操控

所有移动都相对于当前视角的水平朝向 `yaw`：「前」就是屏幕里往前。

- **键盘**：
  - `W` / `↑` 前进，`S` / `↓` 后退。
  - `A` / `D` 左右平移（横着走）。
  - `←` / `→`、`Q` / `E` 连续转向，转速 120°/秒，按住就一直转，不再一次转 90°。
  - 同时按多个键时合成方向，斜向移动速度归一化，不会更快。
- **鼠标**：在画布上按住左键拖动，转 `yaw`（水平）和 `pitch`（竖直）；滚轮缩放跟随视角的距离。
- **触屏**：
  - 画布左半边：手指按下的位置出现虚拟摇杆（底座 + 摇杆头），拖动方向就是移动方向，推得越远走得越快（死区 10%），松手消失。
  - 画布右半边：单指拖动转视角（`yaw` / `pitch`）。
  - 右半边双指捏合：缩放跟随视角的距离。
  - 两只手可以同时操作（左手走、右手转视角），按 `pointerId` 分别跟踪。
  - 手势仲裁（每个指针在 `pointerdown` 时分配角色，之后手指移到另一半边也不改变角色）：
    - 落在左半边、且当前没有摇杆指针 → 成为**摇杆指针**；左半边其余手指忽略。摇杆指针永远不参与捏合。
    - 落在右半边、且当前没有视角指针 → 成为**视角指针**。
    - 落在右半边、已有视角指针、且没有第二个右侧指针 → 两指进入**捏合**：暂停视角拖动，以两指当前距离为基准缩放。右半边第三根及以后的手指忽略。
    - 捏合中抬起其中一指 → 剩下那根恢复为视角指针，以它当前位置为新的拖动基准（不跳变）；再按下新的右侧手指时，以当前两指距离为新基准进入捏合。
    - 任一角色结束时只清除该角色的状态；摇杆指针抬起 → 移动输入归零、摇杆隐藏，视角与捏合不受影响。
    - 鼠标：左键按下即为视角指针（不分左右半边），滚轮缩放。
  - 舞台容器 `#stage` 设置 `touch-action: none`，拖动时页面不滚动、不缩放。
- 原来的四个方向按钮移除，画面下方改为一行操作提示（电脑：「WASD / 方向键移动，拖动鼠标转视角」；触屏：「左边拖动走路，右边拖动转视角」，按 `pointer: coarse` 媒体查询切换显示）。
- 新增「全屏」按钮（支持 Fullscreen API 时显示），手机上全屏后操作空间更大；退出全屏后画布尺寸恢复。

### 视觉效果

- 主题、纹理、光照沿用现有实现。
- 相机移动、转向全部插值平滑，没有跳变。
- 跟随视角可以斜着看，墙的立体感比正上方俯视更明显。
- 小人走路起伏、朝向平滑转动。
- 地板上起点 / 终点 / 道路 / 迷雾颜色语义不变。

### 其他功能保持

- 迷宫生成、seed / size URL 参数、尺寸按钮、重新生成、显示 / 隐藏道路、迷雾开关与视野调节、主题切换、小地图、自动降画质、WebGL 降级提示：全部保留。
- 迷雾和道路都按小人「所在格」计算；所在格变化时重算，与现在一样不必每帧重算。
- 显示道路时，道路从小人所在格算到终点。
- 「再来一局」、重新生成、切换尺寸：小人回到起点格中心，速度清零，朝向朝南（入口在左上角，迷宫在南 / 东方向）。

## 非目标

- 不改迷宫生成；不改 2D 页面。
- 不做跳跃、奔跑键、重力、物理引擎（自己写圆与轴对齐矩形的碰撞即可）。
- 不做陀螺仪、手柄支持。
- 不保存视角角度到 `localStorage`。

## 反目标（做到了也算失败）

- 任何操作下小人穿墙、卡进墙里出不来，或走出迷宫。
- 按住方向键时小人仍然一格一格地跳，或转向仍是一次 90°。
- 触屏拖动时页面跟着滚动或缩放。
- 跟随视角下相机被墙挡住，画面一整片都是墙。
- 帧率比改动前明显下降（同一性能检查平均帧时间增加超过 30%）。

## 方案

### 纯逻辑（`maze-3d/movement.js`，新模块，可在 node 中测试）

- `wallBoxes(segments)`：把 `wallSegments` 的墙段转为轴对齐矩形 `{minX, maxX, minZ, maxZ}`，再补上入口、出口两处外边界开口的封闭矩形。
- `collideCircle(pos, radius, boxes)`：返回把圆推出所有重叠矩形后的位置（按最小穿透方向推出），多次迭代直到不重叠或达到迭代上限。
- `stepPlayer(state, input, dt, boxes)`：纯函数，输入当前位置 / 速度、输入向量（前后、左右，范围 −1–1）、`yaw`、`dt`，输出新的位置 / 速度；内部做加速度、速度上限、子步与碰撞。
- `inputFromKeys(keysDown)`、`inputFromStick(dx, dy, radius, deadZone)`：把按键集合 / 摇杆偏移转成输入向量，斜向归一化。
- `cellOf(pos)`：位置所在格。
- `wallBoxes3d(boxes, height, margin)`：把二维墙矩形转为外扩后的三维包围盒 `{minX, maxX, minY, maxY, minZ, maxZ}`。
- `cameraPullIn(target, cameraPos, boxes3d)`：三维线段 `target → cameraPos` 与包围盒做 slab 求交，取最近交点，返回不被遮挡的相机距离 `d_safe`（无遮挡时等于原距离）。
- `createPointerRouter()`：手势仲裁的纯逻辑状态机，输入 `down / move / up / cancel / reset` 事件（含 `pointerId`、类型、坐标、所在半边），输出摇杆偏移、视角增量、缩放比例。`main.js` 只负责把 DOM 事件转给它。
- 候选碰撞矩形可按格索引加速（只检查所在格及相邻格的墙），保证 20×20 下每帧开销很小。

### 渲染与输入（`main.js`）

- 移除离散移动的状态机（`handleDirection`、`stepAnimation` 等）和方向按钮绑定；保留 `generation` 机制，生成新迷宫时作废进行中的输入状态。
- 每帧：读输入 → `stepPlayer` → 更新小人模型位置 / 朝向 / 起伏 → 所在格变化时重算迷雾、道路、小地图 → 更新相机 → 渲染。
- 输入层用 Pointer Events 统一处理鼠标与触摸。监听器绑定在稳定的舞台容器 `#stage` 上，不绑在 renderer 的 canvas 上：现有 `downgrade()`（`main.js:717`）会用新 canvas 替换旧 canvas，绑在 canvas 上的监听会随之丢失。左右半边按 `#stage` 的 `getBoundingClientRect()` 判断。
- 虚拟摇杆用一个绝对定位的 DOM 元素叠在 `#stage` 内（不进 WebGL 场景），设置 `pointer-events: none`，事件穿透到 `#stage`。
- 指针生命周期：
  - `pointerdown` 分配角色后对 `#stage` 调用 `setPointerCapture(pointerId)`，手指拖出画布后仍能收到后续事件。
  - `pointerup`、`pointercancel`、`lostpointercapture` 走同一个清理函数 `releasePointer(pointerId)`：按该指针的角色清除状态（见手势仲裁），重复调用无副作用。
  - 窗口 `blur`、`visibilitychange` 变为隐藏、重新生成 / 再来一局 / 切换尺寸时，调用 `resetInput()`：清空按键集合、所有指针角色、摇杆位移与显示、捏合基准。
  - 降画质替换 canvas 不影响输入状态，进行中的摇杆继续生效。
- 调试对象 `window.__maze3d` 增加只读 `playerPos`、`playerCell`、`yaw`、`pitch`、`cameraDistance`、`cameraPos`、`cameraTarget`、`wallBoxes3d`（相机避障用的外扩包围盒），以及 `setInputForTest`（仅 `?debug=1` 时存在），供浏览器验收驱动。

### 原有离散移动代码

`game-logic.js` 中的 `findNextIntersection`、`turn`、`resolveInput` 等不再被页面使用；页面不再引用它们，对应的单元测试一并删除，避免留着没人用的代码。`canMove`、`findPath`、`wallSegments`、迷雾相关函数继续使用。

## 测试

自动测试（`node --test tests/`）：

- `tests/maze-3d-movement.test.mjs`：
  - 空地上按住前进 1 秒，位移接近最高速度（考虑加速）；松开后在 0.15 秒内停下。
  - 斜向输入速度不超过最高速度。
  - 正面撞墙停在墙前（圆心到墙面距离 ≥ 半径）；斜着撞墙沿墙滑动（平行墙的分量保留）。
  - 用 `dt = 0.5`（模拟卡顿）朝墙冲，仍不穿墙。
  - 入口、出口处朝迷宫外走，不能离开迷宫范围。
  - 多组 seed 下随机输入跑 2000 帧：小人始终在迷宫范围内，且任一时刻不与任何墙矩形重叠。
  - `inputFromStick` 的死区与归一化；`inputFromKeys` 的组合键。
  - `cameraPullIn`：中间有墙且线段低于墙顶时相机被拉到墙前；无墙时不变；水平投影跨墙、但线段在墙处高于 `WALL_HEIGHT + CAMERA_MARGIN` 时不拉近。
  - 相机距离平滑：给定一串 `d_safe`，`d_cur` 每帧都 ≤ `d_safe`，收近一帧到位，恢复是渐进的。
  - `createPointerRouter`（按事件序列测）：左指摇杆 + 右指视角同时拖动时缩放比例不变；右侧两指进入捏合；捏合中抬起一指后，剩下那根拖动不产生跳变；`cancel` 与 `up` 效果相同；`reset` 后无残留角色、摇杆偏移为 0。
  - 直径 `2 * PLAYER_RADIUS` 的小人能通过净宽 0.9 的通道与 L 形转角。
- 删除离散移动相关的旧单元测试；保留迷宫生成一致性测试不变。
- 页面静态检查：方向按钮已移除；`#stage` 有 `touch-action: none`；摇杆元素有 `pointer-events: none`；存在全屏按钮与两套操作提示文案。

浏览器验收（更新 `tests/browser/maze3d_accept.py`：删除依赖离散移动的检查，新增下列检查；其余主题、迷雾、性能、降级等检查保留并适配连续移动）：

1. 按住 `W` 0.5 秒：小人位置连续变化（逐帧采样，每帧位移都小于 0.1，不出现一格一格的跳变）。
2. 按住 `→` 0.75 秒：`yaw` 连续增加约 90°（误差 ±15°），逐帧变化平滑。
3. 朝墙按住前进 2 秒：小人停在墙前，不穿墙。
4. 模拟触摸（Playwright `touchscreen` / CDP 触摸事件）：左半边拖动摇杆，小人移动；右半边拖动，`yaw` 和 `pitch` 变化；两指同时操作两者都生效，且 `cameraDistance` 不变；页面 `scrollY` 不变。
   - 摇杆手指拖出画布后松开：小人停下、摇杆消失；发送 `touchcancel` 效果相同。
   - 用现有 `?slow=` 参数触发降画质（等到 `quality === 'low'`、`downgradeCount` 为 1）后，键盘、鼠标拖动、触摸摇杆仍然生效。
5. 鼠标拖动改变 `yaw` / `pitch`；滚轮改变跟随距离且在范围内。
6. 跟随视角下走到墙边、`pitch` 设为 15°、把相机转到墙后方向：
   - 几何断言：`cameraTarget → cameraPos` 线段不穿过 `wallBoxes3d` 中任何盒子，`cameraPos` 不在任何盒子内，`cameraDistance` 小于该视角的理想距离。
   - 同一位置 `pitch` 设为 60°：相机不被拉近（从墙顶上方看）。
   - 画面中心颜色多样性只作辅助检查。
   - 保存一张低俯角贴墙截图，供人工确认能看到小人。
7. 用 `setInputForTest` 沿 `findPath` 给出的格子路线走到终点：出现恭喜提示层；「再来一局」后小人回到起点。
8. 迷雾与道路随所在格更新：走进新格子后视野中心随之变化。
9. 切换视角、主题、尺寸、重新生成均正常，无控制台错误。
10. 性能：与现有性能检查同条件（20×20、iPhone SE 模拟 + 4 倍 CPU 降速、同画质），持续移动加转向期间平均帧时间不超过改动前基线的 1.3 倍。
11. 375px 宽：无横向滚动，摇杆区域与按钮不重叠。
12. 每种视角各保存一张截图到 `<repo>/.xdev/<run-id>/screenshots/` 供用户查看。
