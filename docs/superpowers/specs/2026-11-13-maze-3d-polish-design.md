# 3D 迷宫画面打磨设计

## 意图

用户在「还能改进什么」的清单里选定了一批改进（不做「指个方向」提示）。按改动性质拆成三个依次叠加的 PR，本文是第一个 PR「画面打磨」，包含：

1. 开局镜头对准迷宫内部。
2. 小人脚下加圆形软阴影。
3. 墙脚加暗边（假环境光遮蔽）。
4. 终点光柱、闪光粒子，通关彩带。
5. 画面边缘的终点方向指示。

后续 PR：B「玩法」（脚印、声音与震动、计时与最佳成绩、收集星星），C「角色与场景」（可爱角色、外围装饰）。本 PR 不涉及它们。

现状参考（`maze-3d/main.js`）：`yaw` 约定为前方 = `(sin yaw, −cos yaw)`，开局与 `resetPlayer()` 都把 `yaw` 设为 `π`（朝南）。起点在左上角 (0,0)，迷宫在起点的南 / 东方向；跟随视角相机在小人身后。截图显示开局迷宫只占画面一角，另一大半是外围地面。终点只有一颗旋转的黄色星星（`buildStar`），通关只弹出 `#win` 层。

## 目标

### 1. 开局镜头对准迷宫

- 开局、重新生成、切换尺寸、「再来一局」时，`yaw` 设为「从起点格中心指向迷宫中心」的方向（对正方形迷宫即朝东南，`yaw = 3π/4`），小人模型也朝这个方向。
- 跟随视角下，开局画面中迷宫区域（迷宫地板 + 墙）在画面中占比明显增大：取画面中心 60% 区域采样，属于迷宫的像素 ≥ 50%（改动前记录基线作对比）。

### 2. 小人圆形软阴影

- 小人脚下一块贴地的圆形阴影：径向渐变（中心不透明度约 0.35，边缘为 0），半径约为碰撞半径的 1.2 倍。用一张 64×64 的 Canvas 渐变纹理 + `MeshBasicMaterial`（透明、不写深度）实现，放在地板之上 0.005，避免 z-fighting。
- 随小人移动；走路起伏时阴影大小与透明度随高度轻微变化（小人抬高时阴影略小略淡）。
- 第一人称下小人模型隐藏，阴影也隐藏。

### 3. 墙脚暗边

- 每段墙的底部两侧地板上，画一条沿墙方向、宽约 0.18 的暗边：从墙根到外侧由约 0.3 不透明度渐变到 0。
- 实现：一张 1×64 的竖向渐变 Canvas 纹理，贴在一组细长平面上，用一个 `InstancedMesh`（一次绘制）。每段墙两侧各一个实例，位置、朝向与墙段对应；墙段被迷雾隐藏时，对应的暗边实例一起隐藏。
- 暗边颜色取黑色，在四个主题下都只是加深，不改变地板颜色的语义（起点、终点、道路、迷雾格的颜色可分辨检查继续通过）。

### 4. 终点光柱与通关彩带

- 终点格上方加一道半透明光柱：圆柱体，半径 0.35，高 6，颜色金黄，自下而上透明度从 0.45 渐变到 0（竖向渐变纹理），加法混合，不写深度。光柱缓慢脉动（透明度在 0.7–1.0 倍之间随时间正弦变化）。
- 光柱周围有 20 颗上升的小闪光粒子（`Points`，点大小随距离衰减），循环上升、到顶后从底部重生。
- 远处可见：迷雾开启时光柱与粒子**不受迷雾隐藏**，也不受场景距离雾影响（材质 `fog: false`），让孩子随时知道终点在哪。原有黄色星星保留。
- 通关时，在 `#win` 层出现的同时播放彩带：一个覆盖画面的 2D `<canvas>`，约 120 片彩色纸屑从上方落下、旋转飘动，持续约 2.5 秒后淡出并停止绘制。尊重 `prefers-reduced-motion: reduce`：此时不播放彩带。
- 彩带生命周期：
  - 只在 `updatePlayer()` 里 `state` 变为 `'won'` 的那一刻启动（与 `$('win').hidden = false` 同一处）。
  - `buildMaze()` 开头（「再来一局」、重新生成、切换尺寸都经过它）立即取消彩带：停止绘制、清空画布、`confettiActive` 置假。
  - 彩带画布设 `pointer-events: none`，层级在 `#win` 之下，不遮挡「再来一局」按钮。

### 5. 终点方向提示

墙高 `WALL_HEIGHT = 0.8`、第一人称眼高 `EYE_HEIGHT = 0.45`，墙正常写深度；所以「终点投影在画面内」不等于「光柱看得见」：第一人称在走廊里朝向终点时，近处的墙会把整根光柱挡住。因此提示按光柱的**实际可见性**统一分三种状态，任一时刻只处于其中一种：

| 状态 `mode` | 条件 | 表现 |
| --- | --- | --- |
| `'hidden'` | 光柱有采样点在画面内且未被墙遮挡 | 不显示提示 |
| `'marker'` | 光柱有采样点在画面内，但这些点全部被墙遮挡 | 在最高的画面内采样点的屏幕位置（夹到内缩边框内）显示一个轻量标记（小圆点 + 距离），不旋转 |
| `'edge'` | 光柱所有采样点都不在画面内（画面外或相机背后） | 在 `#stage` 内缩 28px 的边框上显示指向终点的箭头 + 距离 |

- 光柱采样点：终点格中心正上方高度 0.4、1.5、3、5 处共 4 个点。「在画面内」= 相机空间深度 `-z > near` 且 NDC 的 x、y 都在 [−1, 1]。
- 遮挡判断：相机位置到采样点的线段与**当前可见的**墙盒子（与 `applyWallVisibility()` 同一判定；迷雾隐藏的墙不算，外扩量为 0）做 slab 求交，与 `cameraPullIn` 同一算法；命中即该点被遮挡。
- 距离显示以格计，四舍五入，例如「6 格」。
- 第一人称与跟随视角都生效；通关后 `mode` 固定为 `'hidden'`。
- 箭头与标记都不拦截触摸和鼠标（`pointer-events: none`），不影响摇杆和拖动视角。
- 箭头方向计算（不做透视除法，避免奇点）：
  1. 取终点格中心（高度 0.4）在**相机空间**的坐标 `(cx, cy, cz)`（`camera.matrixWorldInverse` 变换）。
  2. 屏幕方向取 `(dx, dy) = (cx, −cy)`（CSS 像素坐标系，y 向下）。在相机前方时它与「投影点 − 画面中心」同向（两者只差正的缩放因子 `f / −cz`）；在相机背后时仍给出「目标在左 / 右 / 上 / 下」的正确方向；旋转跨越相机平面（`cz` 经过 0）时连续变化，不出现无穷大。
  3. 若 `hypot(dx, dy) < 1e-6`（终点在视线正后方或正前方），方向取 `(0, 1)`：箭头放在下边框中点、指向下方。
  4. 箭头位置：从画面中心沿 `(dx, dy)` 射出，与内缩 28px 的矩形边框求交（x、y 方向分别求到达参数，取较小者）；角度 `angle = atan2(dy, dx)`。
  5. 输出始终是有限数。

## 非目标

- 不做「指个方向」提示（用户明确不要）。
- 不开实时阴影（`renderer.shadowMap`）；不加后期效果。
- 不改操作、碰撞、迷宫生成、迷雾判定。
- 不做 PR B、C 的内容。

## 反目标

- 开局画面仍是迷宫只占一角。
- 阴影、暗边与地板闪烁（z-fighting），或暗边让某个主题的语义颜色分辨不清。
- 光柱被迷雾隐藏，导致开启迷雾后找不到终点方向。
- 方向箭头挡住摇杆或拖动操作。
- 光柱被墙挡住、方向提示却不显示（提示与实际可见性不一致）。
- 「再来一局」后彩带残留或遮挡按钮。
- 帧率比改动前明显下降（同一性能检查平均帧时间超过改动前的 1.3 倍）。

## 方案

- 新增纯函数（`maze-3d/game-logic.js` 或新模块 `maze-3d/effects.js`，可在 node 中测试）：
  - `startYaw(size)`：起点格中心指向迷宫中心的 `yaw`。
  - `edgeArrow(cam, viewW, viewH, inset)`：输入终点的相机空间坐标 `{x, y, z}`，按「终点方向提示」第 2–5 步返回 `{x, y, angle}`（不判断可见性，只算边框位置）。
  - `endHintMode(samples)`：输入各采样点的 `{inView, occluded}`，返回 `'hidden' | 'marker' | 'edge'`。
  - `segmentBlocked(a, b, boxes)`：线段 a→b 是否与任一盒子相交（slab 法，与 `cameraPullIn` 抽出共用的求交函数）。
  - `wallFootStrips(segments)`：由墙段生成暗边实例的位置与朝向（每段两侧各一个，外边界墙只生成朝内的一侧）。
  - `confettiStep(pieces, dt, h)`：彩带粒子的纯数据步进，便于测试落地后停止。
- `main.js`：创建阴影网格、暗边 `InstancedMesh`、光柱与粒子、方向箭头 DOM、彩带画布；在帧循环中更新；在迷雾重算时同步暗边实例可见性；主题切换不影响它们。
- 新增的纹理（阴影、暗边、光柱渐变）在启动时创建一次，不随主题切换重建，不计入主题纹理数 `textureCount`。
- 调试对象 `window.__maze3d` 增加只读字段：`startYaw`、`endHint`（`{mode,x,y,angle,distance}`）、`beamEnabled`（光柱对象的 `visible` 开关，**不**代表屏幕上看得见；屏幕可见性以 `endHint.mode === 'hidden'` 与截图为准）、`footStripCount`、`confettiActive`。

## 测试

- 单元测试：
  - `startYaw` 对 10 / 15 / 20 尺寸都返回 `3π/4`（误差 1e-9）；按该 `yaw` 前进方向指向迷宫中心。
  - `edgeArrow`：终点在前方偏左 / 右 / 上 / 下 / 角落时箭头落在内缩边框上、角度指向正确；在相机背后偏右时箭头在右边框；正后方（`x = y = 0`）返回下边框中点；侧向跨越相机平面（`x` 固定为 1，`z` 从 +0.5 每步 0.01 变到 −0.5）时输出全部有限、相邻两步位置变化不超过 2px；宽高比 16:9、1:1、9:16 下都落在对应边框上。
  - `endHintMode`：任一点在画面内且未遮挡 → `'hidden'`；画面内的点全部遮挡 → `'marker'`；无点在画面内 → `'edge'`。
  - `segmentBlocked`：穿墙线段为真；越过墙顶（高于 `WALL_HEIGHT`）的线段为假；与墙平行且不接触的线段为假。
  - `wallFootStrips`：实例数 = 内部墙段数 × 2 + 外边界墙段数；每个实例位于墙的一侧且朝向与墙平行。
  - `confettiStep`：所有纸屑落到底后返回结束状态。
- 浏览器验收（扩展现有脚本，原有检查全部保持通过）：
  1. 开局跟随视角：`yaw ≈ 3π/4`；画面中心 60% 区域内迷宫像素占比 ≥ 50%，并记录改动前的基线。
  2. 阴影随小人移动（位置跟随，误差 ≤ 0.01）；第一人称时隐藏。
  3. 暗边：`footStripCount` 等于预期；迷雾外墙段的暗边实例被隐藏；原有语义颜色可分辨检查仍通过。
  4. 光柱（拆成两项，互不替代）：
     - 4a 光柱在视锥内：开启迷雾、终点在迷雾范围外；跟随视角调整 `yaw` 使光柱入画且 `endHint.mode === 'hidden'`；`beamEnabled` 为真，截图中光柱投影区域的平均亮度高于其左右相邻同尺寸区域（阈值在实施时按基线确定并写入脚本）。
     - 4b 光柱在视锥外：转到背对终点，`beamEnabled` 仍为真，`endHint.mode === 'edge'`，箭头角度指向终点方向。
  5. 方向提示：
     - 背对终点时 `mode === 'edge'`、角度指向终点方向；转向终点使光柱可见后 `mode === 'hidden'`。
     - 第一人称在走廊里朝向终点、近处有墙挡住光柱：`mode === 'marker'`，标记在画面内。
     - 跟随视角把相机压到最小 pitch、让墙挡在光柱前：`mode` 与截图中光柱的实际可见性一致（看不见为 `'marker'`，看得见为 `'hidden'`）。
     - 第一人称原地连续拖动转一整圈，每帧记录 `endHint`：`x`、`y`、`angle` 始终有限。
     - 在箭头位置拖动仍能转视角（不拦截指针）。
  6. 通关时 `confettiActive` 为真，约 3 秒内变为假；通关后 0.5 秒内点「再来一局」，`confettiActive` 立即为假、画布已清空、「再来一局」按钮可点；`prefers-reduced-motion: reduce` 下不播放。
  7. 性能：与改动前同条件比较，平均帧时间不超过 1.3 倍。
  8. 四个主题各保存一张开局跟随视角截图、一张背对终点显示箭头的截图到 `<repo>/.xdev/<run-id>/screenshots/` 供用户查看。
