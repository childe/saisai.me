# 拼音学习页 — 设计

日期：2026-10-09
子项目目录：`pinyin/`

## 1. 目的与使用场景

给小朋友（小学一年级）练汉语拼音。三个场景：

1. **预习 / 复习** —— 打开拼音表，像课本那样铺开，点哪个读哪个，四声连着听。
2. **听音辨形** —— 做选择题：听一个音，从若干形近音近的选项里挑出正确的那个。
3. **开口跟读** —— 听标准音，自己读一遍，得到 0–10 颗星和一条声调曲线，看见自己的调跑偏在哪。

使用环境：**iPhone / iPad 的 Safari**。单一目标浏览器，不为其他端做兼容。

成功标准：小朋友不用大人帮忙就能自己听、自己做题、自己跟读；跟读给出的声调判断和家长的耳朵判断基本一致。

非目标（明确不做）：完整音节（声母+韵母组合）的四声、整体认读音节、拼读练习（b-a-bā）、
学习进度长期存档、错题本、多人账号、服务端。

## 2. 内容清单（118 条）

### 声母 23 个，按呼读音合成

教学上声母不能单独发音，读"呼读音"。合成与标注都按呼读音，和课堂一致。

| 声母 | 呼读音 | 声母 | 呼读音 | 声母 | 呼读音 |
|---|---|---|---|---|---|
| b | bo | d | de | g | ge |
| p | po | t | te | k | ke |
| m | mo | n | ne | h | he |
| f | fo | l | le | | |
| j | ji | zh | zhi | z | zi |
| q | qi | ch | chi | c | ci |
| x | xi | sh | shi | s | si |
| | | r | ri | | |
| y | yi | w | wu | | |

### 韵母 24 个 × 四声 = 95 条

- 单韵母 6：a o e i u ü
- 复韵母 9：ai ei ui ao ou iu ie üe er
- 鼻韵母 9：an en in un ün ang eng ing ong

**例外：`er` 没有一声**。现代汉语只有 ér ěr èr，不造 ēr。故 24×4−1 = 95。

**不收 `ê`**：不在课本 24 韵母表内。

### 韵母的合成形式（零声母音节）

TTS 的 `<phoneme alphabet="py" ph="...">` 要求 `ph` 是**合法音节**。
韵母单独呼读时须写成零声母形式，与屏幕上显示的字形不同。
因此数据里 `display`（显示）与 `ssml`（合成）必须分开两个字段：

| 韵母 | 合成 | 韵母 | 合成 | 韵母 | 合成 |
|---|---|---|---|---|---|
| a | a | ai | ai | an | an |
| o | o | ei | ei | en | en |
| e | e | ui | **wei** | in | **yin** |
| i | **yi** | ao | ao | un | **wen** |
| u | **wu** | ou | ou | ün | **yun** |
| ü | **yu** | iu | **you** | ang | ang |
| | | ie | **ye** | eng | eng |
| | | üe | **yue** | ing | **ying** |
| | | er | er | ong | **见下** |

**`ong` 是唯一的例外：普通话没有单独的 `ong` 音节。**
（`weng` 是韵母 ueng，音不同，不能顶替。）

处理方案，按优先级：

1. 先用冒烟测试确认阿里云的 phoneme 引擎是否直接接受 `ong1`~`ong4`
   （它可能按拼音直接映射音素，不查音节表）。若可行且听感正确，直接用。
2. 否则：合成 `dong1`~`dong4`，用能量起点检测找到塞音爆破之后的元音起始点，
   裁掉声母那一段。教学上示范 ong 本来就是「dōng 去掉 d」。
   只有 4 个文件，裁切点落盘进数据便于复核。

这个分支必须在建整条管线之前解决，见实施计划的第一个任务。

合计 23 + 95 = **118 条音频**。

## 3. 数据文件 `data/pinyin.json`

```json
{
  "baseUrl": "https://ohsaisai.oss-cn-shanghai.aliyuncs.com/pinyin/",
  "groups": [
    {
      "id": "shengmu",
      "title": "声母",
      "items": [
        { "id": "b", "display": "b", "readAs": "bo", "ssml": "bo1", "key": "sm/b.mp3" }
      ]
    },
    {
      "id": "danyun",
      "title": "单韵母",
      "items": [
        { "id": "i1", "display": "ī", "base": "i", "tone": 1, "ssml": "yi1", "key": "ym/i1.mp3" }
      ]
    }
  ],
  "confusions": {
    "a": ["o", "e", "ai", "ao"],
    "an": ["ang", "en", "ai"],
    "b": ["p", "d", "f", "m"]
  }
}
```

字段说明：

- `id` —— 全局唯一。声母用字母本身，韵母用 `基础韵母+声调号`（`a1`、`ang4`）。
- `display` —— 屏幕上显示的字形，韵母带调号。
- `readAs` —— 仅声母有，呼读音，表格里作小字标注。
- `ssml` —— 传给阿里云 TTS 的**零声母音节**+声调号，与 `display` 可能不同（`ī` → `yi1`）。
- `key` —— OSS 对象 key，拼在 `baseUrl` 后面。
- `confusions` —— **按基础韵母 / 声母**（不是按带调条目）标注易混同伴，选择题干扰项的来源。

### confusions 的标注依据

- 声母按发音部位与字形：b/p/m/f、d/t/n/l、g/k/h、j/q/x、zh/ch/sh/r、z/c/s，
  外加字形易混对 b/d、p/q。
- 韵母按（**只在本项目收录的 24 个韵母内取值**）：
  前后鼻音对立 an/ang、en/eng、in/ing；
  形近易混 ui/iu、ie/üe、un/ün、u/ü、ai/ei、ao/ou；
  同主元音组 a/ai/ao、e/ei/er、i/in/ing、o/ou/ong。

`build_data.py` 按上述规则生成一份默认 confusions，允许手工在 json 里微调。

## 4. 存储与生成管线

### OSS

沿用 english-audio 的 bucket 与凭证：Endpoint `oss-cn-shanghai.aliyuncs.com`，
Bucket `ohsaisai`，前缀 `pinyin/`。需对 `pinyin/*` 开公共读，跨域规则沿用现有的
允许来源 `https://saisai.me` 的 GET / HEAD。

### 脚本（`pinyin/scripts/`）

| 脚本 | 职责 |
|---|---|
| `build_data.py` | 从内置的声母/韵母定义表生成 `data/pinyin.json`，含默认 confusions |
| `tts_aliyun.py` | 读 json，逐条调阿里云语音合成生成 mp3 到本地目录；幂等（已存在则跳过） |
| `upload_oss.py` | 从 english-audio 复制并改前缀为 `pinyin/`；幂等（已存在且大小一致则跳过） |

TTS 用 SSML 的 `<phoneme alphabet="py" ph="a1">` 精确指定拼音与声调，
**不靠挑汉字去凑声调**。凭证从项目根 `.env` 读，与 english-audio 一致。

依赖用 `uv pip install` 安装，代码用 black 格式化。

## 5. 界面：三个 tab

顶部三个 tab：**拼音表 / 选择题 / 跟读**。视觉沿用 english-audio 风格，
大字号大按钮，**触控目标不小于 44px**（english-audio 评审踩过这个坑）。

### 5.1 拼音表（默认页）

按组铺开：声母 / 单韵母 / 复韵母 / 鼻韵母。
声母每个一格，格下小字标呼读音（`b` 下标「玻 bo」）。
韵母每行一个基础韵母，右侧四格是四声：

```
单韵母
 a    ā   á   ǎ   à
 o    ō   ó   ǒ   ò
```

`er` 那行一声位置留空占位，不可点。

点任意一格即播。每行右端有一个「连播」按钮，把 ā á ǎ à 连着播一遍，四声对比最清楚。

### 5.2 选择题

进来先自动播一遍音。顶部一个大喇叭按钮可无限次重播。
下面是选项网格，每个选项是带调号的拼音大字。

判定：

- **答对** —— 选项变绿、播提示音、连对计数 +1、自动进下一题。
- **答错** —— 所选项变红、正确答案高亮绿色、**自动播一遍正确答案的音**、
  连对计数清零、**需手动点「下一题」**（留出停顿去感受差别）。

#### 自适应难度

选项数在 4 / 6 / 10 三档之间走：

- 起始 4 选 1
- **连对 5 题升一级**（4→6→10）
- 答错降一级（10→6→4），已在最低档则保持
- 顶部显示当前档位与连对数

难度档位存 **sessionStorage**，刷新不丢，关掉标签页即重置。不做长期存档。

#### 干扰项抽取

给定目标条目，按优先级填满 N−1 个干扰项，去重后打乱：

1. 同一基础韵母的其他三个声调（仅韵母题）
2. `confusions` 中列出的同伴，取其各声调条目
3. 同组内随机填充

硬约束：干扰项不得与正确答案的 `display` 相同；所有选项互不相同。

#### 出题范围

可切换：全部 / 只声母 / 只韵母 / **只四声辨别**（同一基础韵母的四个声调互为干扰项，最难的一档）。

### 5.3 跟读

一次练一个拼音。流程：听标准音 → 录音 → 自动打分。

界面自上而下：

1. 当前拼音大字 + 「听标准音」按钮
2. 圆形录音按钮（按住说话）
3. 录完后出现 **0–10 颗星** + 一句话评语
4. **声调曲线图**：灰色虚线为标准音的归一化音高走向，彩色实线为本次录音，叠在同一张图上
5. 并排两个播放按钮：「听标准音」「听我读的」
6. 「再试一次」「下一个」

#### 降级路径

- 麦克风被拒绝 / 不支持 / 录音失败 → 不报错卡死，切到「只能听标准音」状态，
  提示去系统设置里开麦克风权限。
- 录音成功但分析失败 → 退化为只给录音回放，不给星星，明说「这次没分析出来，听听自己读的吧」。

思路与 english-audio 的断网友好提示一致。

## 6. 跟读打分管线

### 6.1 录音采集

**不用 `MediaRecorder`** —— iOS 上输出 AAC/mp4，还要多解一道码。
改为 `getUserMedia` → `AudioContext` → **AudioWorklet** 直接取原始 PCM
（Safari 14.1+ 支持；不可用时退回 `ScriptProcessorNode`）。
同一份 PCM 既喂分析也直接回放。

标准音：`fetch` mp3 → `decodeAudioData` → Float32，解码结果缓存，同一条不重复解。

### 6.2 打分步骤

录完后在主线程同步跑，单音节耗时几十毫秒。

1. **端点检测** —— 短时能量（RMS）找出发声段，掐掉前后静音，两端各留少量余量。
2. **F0 提取** —— 25ms 窗 / 10ms 步，用 pitchy（McLeod 音高法）。
   丢弃清晰度低于阈值的帧，以及落在合理音域之外的帧。
3. **归一化** —— F0 转半音（对数刻度），减去本次发音自身的中位数；
   时间轴插值重采样到固定 20 个点。
   **这一步是小孩嗓音能与标准音比较的关键：只比曲线形状，不比绝对音高。**
4. **声调评分（6 分）** —— 两件事并行：
   - 与标准音的归一化曲线逐点求距离 → 给分
   - 与四声的典型形状模板做分类 → 给话（"你读成二声了"）
5. **声韵母评分（3 分）** —— MFCC 13 维 → **CMVN**（倒谱均值方差归一化，
   抵消说话人差异，这是跨说话人比对能否成立的命门）→ DTW 对齐求距离 → 映射到 0–3 分。
6. **合理性（1 分）** —— 时长落在 0.2–2 秒、能量稳定，确认是在读而非乱吹麦。

总分四舍五入到 0–10 颗星。

### 6.3 关于分数可信度的声明

这 10 分的构成是刻意的：

- **声调 6 分有物理依据，可信。** F0 曲线是从波形直接算出来的客观量。
- **声韵母 3 分是启发式的"像不像"，判别力有限。** 跨说话人的 MFCC+DTW 距离里
  混杂了"音色不同"与"读错了"两种差异，分不干净，能抓住离谱的错，
  分不清 b/p 这类细微对立。
- **合理性 1 分基本是鼓励分。**

把可信的部分放成大头，是这个配比的用意。文档里不把它说成"发音评测"，
它是一个以声调为主的练习反馈。

### 6.4 阈值校准

**所有阈值在第一版只能算合理猜测，必须用真实录音校准。**

做法：一个隐藏调试面板（连点标题三下打开），显示各项原始数值
（F0 曲线距离、模板分类结果、DTW 距离、时长、能量）。
等赛赛录下若干条真实样本后，据此调一轮阈值，并把样本固化为回归 fixture。

### 6.5 评语生成

- 声调模板分类 ≠ 目标声调 → 「读成了 X 声，再听一遍标准音」
- 声调对但 DTW 距离大 → 「声调对了！音还要再像一点」
- 都好 → 「很棒，声调很准！」

## 7. 工程结构

```
pinyin/
  index.html
  styles.css
  main.js            应用外壳、tab 切换
  chart.js           拼音表视图
  quiz.js            选择题：干扰项抽取、难度升降
  shadow.js          跟读视图
  audio.js           播放与解码缓存
  tone-plot.js       声调曲线 canvas 绘制
  scoring/
    record.js        getUserMedia + AudioWorklet 采集 PCM
    pitch.js         F0 提取、归一化、声调分类
    mfcc.js          MFCC + CMVN
    dtw.js           DTW
    score.js         汇总为 0–10
  vendor/
    pitchy.mjs       手工下载的 ESM，README 注明来源与版本
  data/pinyin.json
  scripts/
    build_data.py  tts_aliyun.py  upload_oss.py
    test_build_data.py
  test/
    *.test.js
  README.md
```

**无构建步骤**，原生 ES modules，与仓库现有子项目风格一致。
`mfcc.js` / `dtw.js` 自己实现（各约百行），不引入 Meyda —— 省掉一个
百 KB 级依赖和它的 vendoring 问题，且这两者逻辑直白、易测。
pitch 检测容易在细节上写错，用成熟的 pitchy。

## 10. 本地预览

`fetch` 在 `file://` 下被拦截，需起本地服务：

    python3 -m http.server 8777

**麦克风需要安全上下文**：`localhost` 被视为安全来源，可用；
局域网 IP（如从 iPhone 访问 `http://192.168.x.x:8777`）**不是**安全来源，
`getUserMedia` 会被拒绝。在真机上测跟读必须走 HTTPS —— 部署到 saisai.me，
或本地起一个带自签证书的 HTTPS 服务。这一点在 README 里要写明。
