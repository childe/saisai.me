# 电路实验室：自由画导线与导线上加连接点 设计

## 原始需求

1. 我希望可以自己画导线，而不仅仅是直的。
2. 可以在导线上通过点击创建端点，这样我可以更灵活的连接。

用户选择跳过提问、直接出设计。下文凡标「（设计方决定）」的，都是没和用户逐条确认、由设计方定下的做法。

## 背景与动机

- 现状：从一个端点按住拖到另一个端点，松手后连成导线。路线固定为 L 形（`wireRoute`：先水平后竖直），拐角位置由两端坐标决定，用户改不了。
- 带来的问题：
  - 想绕开元件走线做不到，导线常常压在元件底下或和别的导线重叠，看不出谁连着谁。上一次的「误报短路」截图，最可能的原因就是一根藏在元件下面的导线。
  - 想把三个及以上的端点接到同一个点（并联分支）时，只能从同一个端点拉多根线，画面乱，也不像真实电路图里的「T 形连接点」。
- 目标用户：小朋友在 iPad 上用手指操作。交互要能用手指完成，命中区不小于 44pt（沿用 `MIN_TOUCH_PT`）。

## 目标

1. 画导线时，导线跟着手指走，最后形成一条贴着网格的直角折线（设计方决定：只用横平竖直的线段，不做斜线和曲线，保持电路图风格，两种画风都好看）。
2. 已画好的导线可以调整路线。
3. 可以在导线上的任意格点加一个「连接点」，从它再拉出新导线；画导线时也可以直接拉到另一根导线上，自动在落点处生成连接点。
4. 求解、损坏、任务判定照常工作，连接点就是电路里的一个节点。
5. 每个编辑动作只占一步撤销。

## 非目标

- 斜线、曲线导线。
- 导线交叉处的「跳线弧」画法。交叉但不相连的导线就直接画成交叉，相连必须有连接点圆点（与电路图惯例一致）。
- 自动寻路绕开元件。
- 保存/读取电路（之前已确定不做）。
- 拖动连接点改变位置（设计方决定：先不做，要换位置就删掉重画，避免和「从连接点拉线」的手势冲突）。

## 反目标（做了等于失败）

- 现有电路（任务预设、旧的 L 形导线）的外观或行为发生变化。
- 手指轻点导线原本用来选中、删除，改完后变得难以选中或误删。
- 手指在端点附近一抖就出现锯齿状的楼梯形导线。

## 数据模型

### 导线

```js
{ id, a: { part, term }, b: { part, term }, via?: [[x, y], ...] }
```

- `via` 可选，是导线中间经过的格点（整数网格坐标）。按从 `a` 到 `b` 的顺序排列，只记录拐点，不记录共线的中间点。
- 没有 `via`（或为空数组）时，走线方式完全不变：仍用现在的 L 形，同一元件两端的导线仍用 U 形。这样旧数据和任务预设不受影响。
- 实际画出的路线 = `wireRoute(端点a, via[0])` + 中间各 `via` + `wireRoute(via[末], 端点b)`，再去掉重复点和共线点。元件被移动或旋转后，端点到第一个/最后一个拐点之间如果不再横平竖直，`wireRoute` 会自动补一个直角拐点。所以任何时候画出来的都是直角折线。
- `cloneCircuit` 要深拷贝 `via`。

### 连接点

新增元件类型 `node`（中文名「连接点」）：

- 一个端点 `o`，本地坐标 `[0, 0]`；没有参数，没有拨片。
- 不放进 `PART_TYPES`，所以元件栏里不显示，也不受任务元件数量限制（`remainingPalette` 只统计任务 palette 里列出的类型）。
- 求解：不贡献电导，只当作节点；`readPart` 对它返回 v=0、i=0、p=0。
- 画法：两种画风都画成实心圆点（卡通风：铜色，半径约 7px；符号风：黑色，半径约 5px），盖在导线上方。被选中时有选中描边。
- 旋转对它无意义，选中后的面板不显示旋转按钮，只有「删除」。

## 交互

所有坐标先换成网格坐标；命中优先级不变：端点 > 拨片 > 元件本体 > 导线。连接点的端点也是端点，所以按在连接点上就是按在端点上。

### 1. 画导线（跟手）

- 起点：按在一个端点上，或按在一根导线上（见第 3 节）。
- 拖动过程中，路线由手指轨迹生成（设计方决定的算法，实现方可调参数，但行为要符合下面几条）：
  - 当前线段沿一个方向延伸（横或竖）。手指偏离当前线段所在直线达到 1 格及以上时，才在投影处落一个拐点、换方向。小幅抖动不会产生拐点。
  - 手指往回退到已经走过的线段上时，回退的部分被吃掉（路线不会自己打折回头）。
  - 所有拐点吸附到整数格点，并限制在画布范围内。
- 预览：拖动时画出当前路线；手指下方有可连接目标时，用现有的青色圆圈标出（端点），或在导线上标出将要生成的连接点位置。
- 松手：
  - 落在另一个端点上：生成导线，`via` 为路线的中间拐点。
  - 落在一根导线上（不是起点所在的那根）：在那根导线上离手指最近的格点处生成连接点，把那根导线一分为二，再把新导线连到这个连接点。
  - 落在空白处或落回起点：取消，什么都不生成。
  - 与现有导线端点完全相同（同一对端点）：沿用现规则，不生成。
- 如果手指几乎没有离开起点格就拖到了目标（例如直接拉过去），路线为空或只有一个拐点，效果和现在的 L 形一致。

### 2. 调整已有导线的路线

- 轻点导线选中它（与现在一样），面板显示「删除」。
- 选中的导线在每条线段的中点显示一个拖动把手（圆形，触控区 ≥ 44pt）。
- 按住把手拖动：这条线段沿垂直于自身的方向平移，吸附到格点，两侧相邻线段跟着伸缩，保持直角。若被拖的是连到端点的首段或末段，则在端点一侧自动补一个拐点，让导线仍然从端点出发。
- 一次拖动只算一步撤销（沿用 `coalesce`）。
- 调整后的路线写回该导线的 `via`。

### 3. 在导线上加连接点

- 轻点一根**已选中**的导线：在离手指最近的格点处加一个连接点，把导线分成两段；新的连接点变为选中状态。（设计方决定：第一下仍是选中，第二下才是加点，以免轻点导线就到处冒出圆点，也保留「点选 → 删除」的老用法。）
- 从任意一根导线（选没选中都行）上按住并拖出：等同于先在按下处加连接点、再从连接点画导线。松手时如果没有连到任何目标，就什么都不生成，导线保持原样。
- 分割规则：原导线 `w(a→b, via)` 在格点 `P` 处断开，生成连接点 `N`，得到 `a→N.o`（`via` 取 P 之前的拐点）和 `N.o→b`（`via` 取 P 之后的拐点）两根导线，原导线删除。路线外观不变，只是 P 处多了一个圆点。
- `P` 正好落在导线的端点上时，不分割；这时直接从那个端点出发（起点就是那个端点）。
- 加连接点、分割、连新线都在一个 action 里完成，只占一步撤销。

### 4. 删除

- 删除导线：与现在一样。若删除后某个连接点不再连着任何导线，把这个连接点一并删除。
- 删除连接点（选中后点「删除」）：
  - 恰好连着两根导线：把两根导线合并回一根（`via` 依次拼接，并在连接点位置补一个拐点），连接点消失。
  - 其他情况：删除连接点和与它相连的所有导线。
- 轻点（不拖动）连接点就是选中它。
- 「清空」「撤销」行为不变。

## 求解与其他模块

- `solve.js`：在 `CONDUCTANCES` 中不加 `node`（不贡献电导），`readPart` 为 `node` 加一个分支，返回全 0。并查集、隐含导线（`junctionWires`）对单端点元件同样适用：连接点和别的端点画在同一格点上，也按接通处理。
- `damage.js`、`viewmodel.js`、`tasks.js`：遇到 `node` 时不报错、不显示读数、不参与烧坏和报警。要检查所有按 `type` 分支或按两个端点取值的地方。
- 导线上的电流流动动画按新路线画（`wirePoints` 是唯一的路线来源，视图和命中检测都调用它）。

## 需要改动的地方（供实现方参考，不是限定）

- `lib/parts.js`：新增 `node` 定义（不进 `PART_TYPES`）。
- `lib/geometry.js`：`wirePoints` 支持 `via`；新增「由手指轨迹生成直角路线」「线段拖动」「导线上最近格点」等纯函数；`hitTest` 能返回导线命中点与线段序号。
- `lib/circuit.js`：`addWire` 接收 `via`；新增分割导线、合并、移动线段、带清理的删除。
- `lib/editor.js`：`connect` 支持起点/终点为「导线上的点」；新增 `splitWire`、`moveWireSegment`（可 coalesce）等 action；删除连接点的合并逻辑。
- `lib/drawings.js`：画 `node`。
- `app.js` / `view.js`：手势改造、选中导线的把手、预览。
- 测试：放在 `circuit/test/`，沿用 `node:test`。

## 验收

自动化测试（`node --test circuit/test`）全部通过，并新增覆盖：

1. 轨迹 → 路线：直线拖动不产生拐点；小于 1 格的抖动不产生拐点；L 形、U 形、回退轨迹得到预期的拐点序列；结果全部横平竖直、位于格点。
2. 路线：没有 `via` 的导线，`wirePoints` 的结果与改动前完全一致（包括同元件 U 形）；有 `via` 时首尾在元件移动、旋转后仍为直角折线。
3. 分割：分割后两段导线拼起来的路线与原路线相同；在端点处分割被拒绝；一步撤销恢复原状。
4. 求解：用连接点做的并联（电池 → 连接点 → 两盏灯 → 连接点 → 电池）与直接从同一端点拉两根线的并联，各灯功率相同（误差 1e-9 以内）。
5. 删除：删除两线连接点后合并为一根导线且路线不变；删除导线后孤立连接点被清理。
6. 线段拖动：拖动后仍为直角折线，端点不动，一次拖动只产生一条撤销记录。
7. `node` 在两种画风下都能画出，没有 NaN/undefined；不出现在元件栏中。
8. 所有现有测试（任务、求解、绘图、静态检查）不变通过。

手动验收（iPad Safari）：

- 画一条绕开元件的 Z 形导线，再拖动中段把手调整它。
- 在一根导线中间加连接点，从它拉出一根导线接到一盏灯，灯按并联正确发光。
- 从一根导线上直接拖出一根新导线，连到另一根导线上，两头都自动生成连接点。
