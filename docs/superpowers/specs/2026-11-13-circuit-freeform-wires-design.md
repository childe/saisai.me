# 电路实验室：自由画导线与导线上加连接点 设计

## 原始需求

1. 我希望可以自己画导线，而不仅仅是直的。
2. 可以在导线上通过点击创建端点，这样我可以更灵活的连接。

用户选择跳过提问、直接出设计。下文凡标「（设计方决定）」的，都是没和用户逐条确认、由设计方定下的做法。

## 背景与动机

- 现状：从一个端点按住拖到另一个端点，松手后连成导线。路线固定为 L 形（`wireRoute`：先水平后竖直），拐角位置由两端坐标决定，用户改不了。
- 带来的问题：
  - 想绕开元件走线做不到，导线常常压在元件底下或和别的导线重叠，看不出谁连着谁。上一次的「误报短路」截图，最可能的原因就是一根藏在元件下面的导线。
  - 想把三个及以上的端点接到同一个点（并联分支）时，只能从同一个端点拉多根线，画面乱，也不像真实电路图里的「T 形连接点」。
- 目标用户：小朋友在 iPad 上用手指操作。交互要能用手指完成，命中区不小于 44pt（沿用 `MIN_TOUCH_PT`）。

## 目标

1. 画导线时，导线跟着手指走，最后形成一条贴着网格的直角折线（设计方决定：只用横平竖直的线段，不做斜线和曲线，保持电路图风格，两种画风都好看）。
2. 已画好的导线可以调整路线。
3. 可以在导线上的任意格点加一个「连接点」，从它再拉出新导线；画导线时也可以直接拉到另一根导线上，自动在落点处生成连接点。
4. 求解、损坏、任务判定照常工作，连接点就是电路里的一个节点。
5. 每个编辑动作只占一步撤销。

## 非目标

- 斜线、曲线导线。
- 导线交叉处的「跳线弧」画法。交叉但不相连的导线就直接画成交叉，相连必须有连接点圆点（与电路图惯例一致）。
- 自动寻路绕开元件。
- 保存/读取电路（之前已确定不做）。
- 拖动连接点改变位置（设计方决定：先不做，要换位置就删掉重画，避免和「从连接点拉线」的手势冲突）。

## 反目标（做了等于失败）

- 现有电路（任务预设、旧的 L 形导线）的外观或行为发生变化。
- 手指轻点导线原本用来选中、删除，改完后变得难以选中或误删。
- 手指在端点附近一抖就出现锯齿状的楼梯形导线。

## 数据模型

### 导线

```js
{ id, a: { part, term }, b: { part, term }, via?: [[x, y], ...], r?: number }
```

- `via` 区分两种模式（设计方决定，避免空数组一词两义）：
  - **自动走线**：没有 `via` 字段（`undefined`）。走线方式完全不变：仍用现在的 L 形，同一元件两端的导线仍用 U 形。旧数据和任务预设都是这种。
  - **显式路线**：有 `via` 字段，是一个数组（**包括空数组**）。实际路线 = 端点a → 各 `via` → 端点b，相邻两点之间用 `wireRoute` 连接（不横平竖直时自动补一个直角拐点），再去掉重复点和共线点。空数组表示「从 a 直接 `wireRoute` 到 b」，即使 a、b 是同一元件的两端也**不**套用 U 形。
- 凡是新画、调整、分割、合并产生的导线，一律写显式路线（数组），不会写回 `undefined`。自动走线只来自旧数据和任务预设。
- `via` 按从 `a` 到 `b` 的顺序排列，只记录拐点，不记录共线的中间点。坐标通常是整数格点；**唯一例外**是从旧的同元件 U 形导线分割、合并得来的路线：U 形横段在半格坐标上（`SELF_WIRE_OFFSET = 1.5`），这些半格拐点原样保存，不吸附到整数格点，以保证外观不变。
- 元件被移动或旋转后，端点到第一个/最后一个拐点之间如果不再横平竖直，`wireRoute` 会自动补一个直角拐点。所以任何时候画出来的都是直角折线。
- 在 `geometry.js` 统一提供三个纯函数，所有编辑都走它们：`expandRoute(circuit, wire)`（两种模式都展开成完整折线，即 `wirePoints`）、`splitRoute(points, P)`（在折线上的点 P 处切成两段，返回两段各自的显式 `via`）、`joinRoute(via1, P, via2)`（以 P 为拐点拼接，去掉共线点）。分割、合并都基于**展开后的完整折线**计算，不基于原 `via` 字段，所以自动走线的导线（包括 U 形）也能正确分割。
- `cloneCircuit` 要深拷贝 `via`，并保留「没有 `via`」与「空数组」的区别；`r` 是数字，随导线一起拷贝。

### 导线电阻（设计方决定）

- 求解器里每根导线都是一个 `R_WIRE = 0.001Ω` 的电阻（`solve.js:134` 加电导，`solve.js:235` 算导线电流），这是「理想导线」的数值近似。它不能忽略：在低阻回路里，0.001Ω 和其他电阻在同一量级。例如单节电池（内阻 0.1Ω）直接接电流表（0.01Ω），用两根导线连成回路，电流为 1.5 / 0.112 ≈ 13.39 A；如果分割后每段都按整根 `R_WIRE` 算，加一个连接点就变成 1.5 / 0.113 ≈ 13.27 A，读数明显改变，连续加点会继续下降。
- 因此导线新增可选字段 `r`（这根导线的电阻）：
  - 没有 `r` 时按 `R_WIRE`。旧数据、任务预设、新画的导线、隐含导线（`junctionWires`）都不写 `r`，行为与现在完全相同。
  - **分割**：原导线电阻 `R = w.r ?? R_WIRE`，两段各得 `R / 2`（写入 `r`）。在已分出的半段上再加点就继续对半分，这段路的总电阻始终等于原导线电阻。
  - **合并**（删除恰好连两根导线的连接点）：新导线 `r = r1 + r2`（缺省的一方按 `R_WIRE`）。所以「加点再删点」回到原值；两根各自画出的导线经连接点合并，得到 `2 × R_WIRE`，与合并前两根串联的电阻相同，读数也不变。
  - 对半与相加都是 2 的幂次缩放，在合理的加点次数内浮点运算是精确的，合并后 `r` 与原值逐位相等。
- `solve.js` 两处都改用 `w.r ?? PHYS.R_WIRE`：加电导用 `1 / R`，导线电流用 `(va - vb) / R`。
- 结论：**只加连接点、不接分支，任何回路（包括上面的低阻回路）的求解结果都不变**，界面读数字符串不变。
- 仍有差异的情况：用连接点做的并联，与「从同一端点拉多根线」的并联，导线条数和结构不同，电阻不完全相同。这与现状一致（现在从同一端点拉两根线并联，和先连到另一个端点再分出去，导线电阻也不一样）。本设计不消除这种差异，也不承诺两者读数相同；验收只在普通灯泡回路上用相对误差 1e-3 比较。

### 连接点

新增元件类型 `node`（中文名「连接点」）：

- 一个端点 `o`，本地坐标 `[0, 0]`；没有参数，没有拨片。
- 不放进 `PART_TYPES`，所以元件栏里不显示，也不受任务元件数量限制（`remainingPalette` 只统计任务 palette 里列出的类型）。
- 求解：不贡献电导，只当作节点；`readPart` 对它返回 v=0、i=0、p=0。
- 画法：两种画风都画成实心圆点（卡通风：铜色，半径约 7px；符号风：黑色，半径约 5px），盖在导线上方。被选中时有选中描边。
- 旋转对它无意义，选中后的面板不显示旋转按钮，只有「删除」。

## 交互

所有坐标先换成网格坐标；命中优先级：端点 > **选中导线的把手** > 拨片 > 元件本体 > 导线。没有选中导线时，与现在完全相同。`hitTest` 新增命中类型 `{ kind: 'handle', wire, seg }`，只对当前选中的那根导线计算。连接点的端点也是端点，所以按在连接点上就是按在端点上。

按下（pointerdown）时根据命中类型**锁定手势**，之后整个手势只做这一类事，移动中不再改判：按在端点上 → 画导线；按在把手上 → 调整路线；按在导线（非把手区域）上 → 轻点加点/选中，或拖出分支。

### 1. 画导线（跟手）

- 起点：按在一个端点上，或按在一根导线上（见第 3 节）。
- 拖动过程中，路线由手指轨迹生成（设计方决定的算法，实现方可调参数，但行为要符合下面几条）：
  - 当前线段沿一个方向延伸（横或竖）。手指偏离当前线段所在直线达到 1 格及以上时，才在投影处落一个拐点、换方向。小幅抖动不会产生拐点。
  - 手指往回退到已经走过的线段上时，回退的部分被吃掉（路线不会自己打折回头）。
  - 所有拐点吸附到整数格点，并限制在画布范围内。
- 预览：拖动时画出当前路线；手指下方有可连接目标时，用现有的青色圆圈标出（端点），或在导线上标出将要生成的连接点位置。
- 松手：
  - 落在另一个端点上：生成导线，`via` 为路线的中间拐点。
  - 落在一根导线上（不是起点所在的那根）：在那根导线上离手指最近的点（取法见第 3 节）生成连接点，把那根导线一分为二，再把新导线连到这个连接点。
  - 落在空白处或落回起点：取消，什么都不生成。
  - 与现有导线端点完全相同（同一对端点）：沿用现规则，不生成。
- 如果手指几乎没有离开起点格就拖到了目标（例如直接拉过去），路线为空或只有一个拐点，效果和现在的 L 形一致。

### 2. 调整已有导线的路线

- 轻点导线选中它（与现在一样），面板显示「删除」。
- 选中的导线在每条线段的中点显示一个拖动把手（圆形，触控区 ≥ 44pt）。
- 按住把手拖动（移动超过现有 `DRAG_PX`）：这条线段沿垂直于自身的方向平移，吸附到格点，两侧相邻线段跟着伸缩，保持直角。若被拖的是连到端点的首段或末段，则在端点一侧自动补一个拐点，让导线仍然从端点出发。把手区域内的拖动**只调整路线，不拉分支**；要从这一段拉分支，从把手以外的导线区域按下。
- 轻点把手（没有超过 `DRAG_PX`）：等同于轻点已选中的导线，即在离手指最近的点加连接点（见第 3 节）。这样把手不会挡住线段中间加点。
- 一次拖动只算一步撤销（沿用 `coalesce`）。拖动过程中实时提交（与现在拖元件相同）；手势被系统取消（`pointercancel`）时保留已提交的结果，不额外回滚，和现在拖元件被取消的行为一致。
- 调整后的路线写回该导线的 `via`。

### 3. 在导线上加连接点

- 轻点一根**已选中**的导线：在离手指最近的点（取法见下文）加一个连接点，把导线分成两段；新的连接点变为选中状态。（设计方决定：第一下仍是选中，第二下才是加点，以免轻点导线就到处冒出圆点，也保留「点选 → 删除」的老用法。）
- 从任意一根导线（选没选中都行）上按住并拖出：等同于先在按下处加连接点、再从连接点画导线。松手时如果没有连到任何目标，就什么都不生成，导线保持原样。
- 「离手指最近的点」`P` 的取法（设计方决定）：先把手指投影到导线展开后折线上最近的那条线段，再**只沿该线段方向**取整到整数格，垂直方向保持线段本身的坐标，并夹在线段两端之间。普通导线上 P 就是整数格点；旧 U 形导线的半格横段上，P 的一个坐标是半格（例如 `y = 1.5`），这时连接点也放在这个半格位置。
- 分割规则：原导线 `w(a→b)` 用 `expandRoute` 展开成完整折线，在 `P` 处用 `splitRoute` 断开，生成连接点 `N`，得到 `a→N.o`（`via` 取 P 之前的拐点）和 `N.o→b`（`via` 取 P 之后的拐点）两根显式路线导线，两段的 `r` 各为原导线电阻的一半（见「导线电阻」），原导线删除。路线外观不变，只是 P 处多了一个圆点。对旧 U 形导线，两段的 `via` 里带上原 U 形的半格拐点。
- `P` 正好落在导线的端点上时，不分割；这时直接从那个端点出发（起点就是那个端点）。
- 加连接点、分割、连新线都在一个 action 里完成，只占一步撤销。

### 4. 删除

- 删除导线：与现在一样。若删除后某个连接点不再连着任何导线，把这个连接点一并删除。
- 删除连接点（选中后点「删除」）：
  - 恰好连着两根导线：把两根导线合并回一根（用 `joinRoute` 把两段展开后的拐点依次拼接，在连接点位置补一个拐点，再去掉共线点；结果总是显式路线；`r` 为两段电阻之和），连接点消失。
  - 其他情况：删除连接点和与它相连的所有导线。
- 轻点（不拖动）连接点就是选中它。
- 「清空」「撤销」行为不变。

## 求解与其他模块

- `solve.js`：在 `CONDUCTANCES` 中不加 `node`（不贡献电导），`readPart` 为 `node` 加一个分支，返回全 0。导线电阻改为 `w.r ?? R_WIRE`（加电导和算导线电流两处），见「导线电阻」一节。并查集、隐含导线（`junctionWires`）对单端点元件同样适用：连接点和别的端点画在同一格点上，也按接通处理。
- `damage.js`、`viewmodel.js`、`tasks.js`：遇到 `node` 时不报错、不显示读数、不参与烧坏和报警。要检查所有按 `type` 分支或按两个端点取值的地方。
- 导线上的电流流动动画按新路线画（`wirePoints` 是唯一的路线来源，视图和命中检测都调用它）。

## 需要改动的地方（供实现方参考，不是限定）

- `lib/parts.js`：新增 `node` 定义（不进 `PART_TYPES`）。
- `lib/geometry.js`：`wirePoints` 支持 `via`；新增「由手指轨迹生成直角路线」「线段拖动」「导线上最近格点」等纯函数；`hitTest` 能返回导线命中点与线段序号。
- `lib/circuit.js`：`addWire` 接收 `via`；新增分割导线（对半分 `r`）、合并（`r` 相加）、移动线段、带清理的删除。
- `lib/solve.js`：导线电阻读 `w.r ?? PHYS.R_WIRE`；`readPart` 加 `node` 分支。
- `lib/editor.js`：`connect` 支持起点/终点为「导线上的点」；新增 `splitWire`、`moveWireSegment`（可 coalesce）等 action；删除连接点的合并逻辑。
- `lib/drawings.js`：画 `node`。
- `app.js` / `view.js`：手势改造、选中导线的把手、预览。
- 测试：放在 `circuit/test/`，沿用 `node:test`。

## 验收

自动化测试（`node --test circuit/test`）全部通过，并新增覆盖：

1. 轨迹 → 路线：直线拖动不产生拐点；小于 1 格的抖动不产生拐点；L 形、U 形、回退轨迹得到预期的拐点序列；结果全部横平竖直、位于格点。
2. 路线：没有 `via` 的导线，`wirePoints` 的结果与改动前完全一致（包括同元件 U 形）；有 `via` 时首尾在元件移动、旋转后仍为直角折线。
3. 分割：分割后两段导线拼起来的路线与原路线相同；在端点处分割被拒绝；一步撤销恢复原状。同元件 U 形导线在四种旋转下，分别在横段（半格）和竖段上分割，再删除连接点合并，每一步的展开路线都与原 U 形路线逐点相同。
4. 路线模式：没有 `via` 的导线走自动 L/U 形；`via: []` 的同元件导线不套用 U 形；`cloneCircuit` 后两种模式与 `r` 保持不变。
5. 求解：
   - 没有 `r` 的导线求解结果与改动前逐位相同（现有求解测试不改即通过）。
   - 只加连接点、不接分支：分别用 (a) 电池—灯回路、(b) 单节电池—电流表低阻回路（改动前约 13.39 A）。在同一根导线上连续加 1、2、3 个连接点（包括在已分出的半段上再加），每一步所有元件的 v、i、p 与加点前相对误差 1e-9 以内，`viewmodel` 读数字符串完全相同；再逐个删除连接点合并，最后导线 `r` 与原值相等，求解结果与加点前逐位相同。
   - 合并两根各自画出的导线：合并前后求解结果相对误差 1e-9 以内，合并后 `r = 2 × R_WIRE`。
   - 用连接点做的并联（电池 → 连接点 → 两盏灯 → 连接点 → 电池）与直接从同一端点拉两根线的并联，各灯功率相对误差 1e-3 以内，两盏灯都亮、都不烧坏。
6. 删除：删除两线连接点后合并为一根导线且路线不变；删除导线后孤立连接点被清理。
7. 线段拖动：拖动后仍为直角折线，端点不动，一次拖动只产生一条撤销记录。
8. 把手命中：未选中导线时 `hitTest` 结果与改动前一致；选中导线后，线段中点返回 `handle`，同一位置在端点触控区内时仍返回 `terminal`；导线上把手以外的位置返回 `wire`。
9. `node` 在两种画风下都能画出，没有 NaN/undefined；不出现在元件栏中。
10. 所有现有测试（任务、求解、绘图、静态检查）不变通过。

手动验收（iPad Safari）：

- 画一条绕开元件的 Z 形导线，再拖动中段把手调整它；拖动把手时不会拉出新导线。
- 轻点中段把手，在把手位置加出连接点。
- 在一个元件两端之间连一根 U 形导线，在 U 形底部横段上加连接点，导线外观不变。
- 在一根导线中间加连接点，从它拉出一根导线接到一盏灯，灯按并联正确发光。
- 从一根导线上直接拖出一根新导线，连到另一根导线上，两头都自动生成连接点。
