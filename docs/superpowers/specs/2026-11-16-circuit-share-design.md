# 电路实验室：用链接分享电路 设计

## 原始需求

把自己在「自由搭建」里搭好的电路通过 URL 分享给朋友；朋友打开后可以接着改。分享出去的链接同时起到「存档」作用。不需要截图。

下文凡标「（设计方决定）」的，是没和用户逐条确认、由设计方定下的做法。

## 背景

- saisai.me 是纯静态站（GitHub Pages），没有后端，电路只能放进链接本身。
- 现在电路只在内存里，刷新就没了，没有任何保存或导出。
- 电路数据很小：`parts`（id、type、x、y、rot、params）和 `wires`（id、a、b、可选 via、可选 r），见 `circuit/lib/circuit.js`。

## 目标

1. 工具栏加「🔗 分享」按钮。点一下，把当前自由搭建的电路编码进链接，复制到剪贴板，并提示「链接已复制」。
2. 打开这条链接：进入自由搭建模式，画板上是链接里的电路，可以照常编辑、撤销。
3. 链接就是点「分享」那一刻电路的存档；之后的改动不会写回链接。

## 非目标

- 改动时自动更新地址栏（用户明确不要）。
- 本地自动保存（localStorage）。
- 截图或预览图。
- 分享小任务关卡的进度。
- 短链接服务。

## 方案选择

| 方案 | 说明 | 结论 |
|------|------|------|
| A. 地址栏随改动自动更新 + 分享按钮 | 刷新不丢，但地址栏一直在变 | 不选：用户要的「保存」是指分享出去的链接，不是每次改动都存 |
| **B. 只有分享按钮** | 点按钮才生成链接，地址栏平时不变 | **用户选定** |
| C. 分享按钮 + localStorage 自动保存 | 刷新不丢，但多一套保存机制，要处理优先级 | 不选：同 A |

## 设计

**链接格式**（设计方决定）：`https://saisai.me/circuit/#c=<数据>`。放在 hash 里，不会发到服务器，也不受静态站限制。数据 = 带版本号的紧凑 JSON → `deflate-raw`（浏览器自带 `CompressionStream`）→ base64url。版本号让以后改数据格式时旧链接还能打开。

**写进链接的内容**：parts 和 wires 的全部字段，加 `nextId`。不写 `rev`、`topoRev`、撤销历史、损坏状态（烧坏的灯、熔断的保险丝），打开后都是好的（设计方决定）。

**打开链接时**（设计方决定）：

- 解码成功：切到自由搭建模式，载入电路，撤销栈为空，视野自动缩放到能看全电路。地址栏保留 `#c=...`，所以接着改后刷新，会回到链接里的原始电路——这正是「存档」的含义。
- 解码失败或数据不合法（未知元件类型、导线连到不存在的端点等）：用现有的 `#banner` 提示「链接里的电路打不开」，画板是空的。
- 载入时逐个校验，不信任链接里的数据：元件类型必须在 `PARTS` 里、参数必须 `isValidParam`、导线两端必须是存在的端点。

**分享按钮**（设计方决定）：

- 只在自由搭建模式显示；小任务模式隐藏。
- 画板为空时点击，提示「先搭一个电路再分享」，不生成链接。
- 复制成功：短暂提示「链接已复制，发给朋友吧」。
- 剪贴板不可用（权限被拒等）：弹出一个小框，里面是选中状态的链接文本，让用户手动复制。
- 点分享不改地址栏。

## 留给实现方

- 紧凑 JSON 的具体字段排列（例如元件写成数组 `[type, x, y, rot, params]`）。
- 编解码函数放在 `circuit/lib/` 下的新模块，纯函数，配单元测试：往返编码后电路相同；各种坏数据都被拒绝而不是抛异常。
- 提示的样式沿用现有 `#banner` / `#confirm` 的风格。
