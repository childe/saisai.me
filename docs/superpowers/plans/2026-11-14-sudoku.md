> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 新增 `sudoku/` 模块：4 章技巧小题（离线预生成）+ 自由练习（页面现场生成），分层提示、不给数字，填错上限与提示上限。

**Architecture:** 纯逻辑放 `sudoku/lib/`，全部是可被 `node --test` 直接测的纯函数：盘面几何 → 暴力解计数 → 4 种技巧的逻辑求解器 → 生成器 / 提示 / 游戏状态机。`tools/gen-drills.mjs` 用同一套逻辑离线生成 `data/drills.js`。页面层（`app.js` + `view.js`）只做渲染和事件转发，所有规则走 `game.js` 的 `act()`。

**Tech Stack:** 原生 HTML/CSS/ES modules，无构建、无依赖；测试 `node --test`（Node 26）。

**Spec:** `docs/superpowers/specs/2026-11-14-sudoku-design.md`

## Global Constraints

- 「填错马上提示」默认开启。
- 提示数据里不得出现「目标格 + 数字」的放置答案。
- `localStorage` 读写全部包 try/catch。

**通用数据约定**（所有任务共用）：
- 格子编号 `cell = row * size + col`，从 0 开始。
- 盘面字符串按行展开，`'1'..'9'` 为数字，`'.'` 为空。
- `values`：长度 `size*size` 的数字数组，0 表示空。
- 候选用位掩码：第 `d` 位（`1 << d`）表示数字 `d` 可填。
- 已证明可删的候选 `eliminated`：`Set<string>`，元素为 `` `${cell}:${digit}` ``。

测试共用 6×6 夹具（放 `sudoku/test/fixtures.js`，Task 1 创建）：

export const PUZ6 = '.234564.612323.564564.313126.564531.';
export const HOLES6 = [0, 7, 14, 21, 28, 35];

### Task 2: 4 种技巧与逻辑求解器

**Files:**
- Create: `sudoku/lib/techniques.js`, `sudoku/test/techniques.test.js`

**Interfaces:**
- Consumes: Task 1 全部
- Produces:
  - `TECHNIQUES = ['hidden', 'naked', 'locked', 'pair']`（从易到难）
  - Step 类型：
    - `{ technique: 'hidden', cell, digit, unit: Unit }`
    - `{ technique: 'naked', cell, digit }`
    - `{ technique: 'locked', digit, from: Unit, to: Unit, cells: number[], eliminations: {cell, digit}[] }`（`from` 是候选被锁住的单元，`cells` 是该数字在 `from` 里的候选格，`to` 是被删候选的单元；pointing 时 from=宫、to=行/列，claiming 时相反）
    - `{ technique: 'pair', unit: Unit, cells: [a, b], digits: [x, y], eliminations: {cell, digit}[] }`
    - `locked`/`pair` 只返回 `eliminations` 非空的步。
  - `findSteps(values, spec, eliminated, technique) → Step[]`
  - `findStep(values, spec, eliminated, allowed = TECHNIQUES) → Step | null`：按 `allowed` 中从易到难的顺序，返回第一个有步的技巧的第一步（顺序确定、可复现）
  - `applyStep(values, eliminated, step) → { values, eliminated }`（返回新对象，不改入参）
  - `logicalSolve(values, spec, allowed = TECHNIQUES) → { solved: boolean, steps: Step[], hardest: string | null, values }`：从空的 `eliminated` 开始反复 `findStep` + `applyStep`；`hardest` 为用过的最难技巧

- [ ] **Step 2: 运行确认失败** → FAIL
- [ ] **Step 3: 实现 `drill-gen.js`**。这一算法由计划指定：
  1. 用 `generateFree` 的挖空方式得到一个只用本章及之前技巧可解、且解题过程用到本章技巧的题。
  2. 用 `logicalSolve` 走一遍，找第一个本章技巧的步，且这一步之前没有出现过删候选的步（`locked`/`pair`），取这一步之前的 `values` 作为快照。没有这样的步就换题。
  3. 在快照上反复随机挑一个空格填入正解，填后若 `drillOk` 仍成立就保留，直到空格数 ≤ `maxEmpty` 或没有能填的格。
  4. 最终 `drillOk` 成立且空格 ≤ `maxEmpty` 则返回，否则返回 null。

- 各层内容（文案可改，结构按此）：

| 技巧 | 层 1 | 层 2 | 层 3 |
|---|---|---|---|
| hidden | `focusCells` = 单元格子，「这里有个数能确定」 | `digit` + `digitCells` = 盘面上所有该数字的格，「看看 N」 | 层 2 内容 + `shadeCells` = 与 `digitCells` 中任一格同行或同列的全部空格（目标格因可填该数字，自然不在其中） |
| naked | `focusCells` = 目标格所在行、列、宫的全部格，「这里有个格能确定」 | `flashCell` = 目标格，「这一格只能填一个数」 | `flashCell` + `digitCells` = 同伴格中已填数字的格；若目标格有被 `eliminated` 删掉的候选，`strike` 列出它们 |
| locked | `focusCells` = `from` 单元，「这一宫里有个数很特别」（from 为行/列时写「这一行/列」） | `digit` + `outlineCells` = `step.cells` | 层 2 + `strike` = `step.eliminations` |
| pair | `focusCells` = 单元，「这里有两个格是一对」 | `outlineCells` = 两格 + `showCandidates` 两格的 `digits` | 层 2 + `strike` = `step.eliminations` |

### Task 6: 做题状态机

**Files:**
- Create: `sudoku/lib/game.js`, `sudoku/test/game.test.js`

**Interfaces:**
- Consumes: Task 1、2、5
- Produces:
  - `MAX_MISTAKES = 5`，`MAX_HINTS = 5`
  - `createGame({ size, puzzle, solution, instantCheck: boolean, autoCandidates: boolean }) → Game`
  - `act(game, action) → Game`（返回新对象；无效动作返回原对象 `===`）。动作：`{type:'tapCell', cell}`、`{type:'digit', digit}`、`{type:'erase'}`、`{type:'toggleNotes'}`、`{type:'undo'}`、`{type:'hint'}`、`{type:'restart'}`
  - `Game` 字段：`size, spec, puzzle, solution`（数组）、`values, given: boolean[], notes: number[]`（位掩码）、`eliminated: Set`、`selected: number|null`、`held: number|null`、`notesMode: boolean`、`instantCheck`、`mistakes`、`wrong: Set<number>`（当前标红的格）、`hintsUsed`、`hint: { step, layer, view } | null`、`status: 'playing'|'failed'|'won'`、`history: object[]`
  - 派生函数：`heartsLeft(g)`、`hintsLeft(g)`、`stars(g)`（0 次 3、1–2 次 2、≥3 次 1）、`highlightDigit(g)`（`held`，否则选中格的数字，否则 null）、`doneDigits(g) → Set<number>`（盘面上已出现 `size` 次的数字）、`isFull(g)`
- 规则（spec「填数」「笔记」「填错处理」「撤销」「过关」「提示」节）：
  - `tapCell`：有 `held` 且该格非题面 → 填入 `held`（笔记模式下切换该候选）；否则选中该格并清掉 `held`。
  - `digit`：有选中的非题面格 → 填入；选中的是题面格 → 无效；没有选中格 → `held` 切换为该数字（再按同一个数字放下）。
  - 填入非笔记数字：清掉同伴格笔记里的该数字；若 `instantCheck` 且与解不同 → 加入 `wrong`，`mistakes + 1`；同一格再填同一个错数不扣；`mistakes` 到 5 → `status = 'failed'`。
  - `instantCheck` 关闭：填错不提示；盘面填满且有错 → 把错格放进 `wrong`；改对后从 `wrong` 移除。
  - 盘面全对 → `status = 'won'`。
  - `hint`：盘面有错数（与解不同的已填格）→ `hint.view = wrongView(...)`，不消耗次数。否则：同一 step 且 layer < 3 → layer + 1，消耗 1 次；已是 layer 3 → 无效、不消耗；无 hint 或盘面已变 → 用 `findStep(values, spec, eliminated)` 取步，layer 1，消耗 1 次。`hintsUsed` 到 5 后无效。`findStep` 返回 null → `hint.view = stuckView()`，不消耗次数。locked/pair 到 layer 3 时把 `eliminations` 加入 `eliminated`、并从 `notes` 删掉，记入 `history`。
  - 任何填数、擦除、笔记修改都清空 `hint`（盘面变化，下次从层 1 开始）。
  - `undo`：撤销最近一条填数 / 擦除 / 笔记修改 / 提示划候选；不恢复 `mistakes` 和 `hintsUsed`。
  - `restart`：同题回到初始，`mistakes`、`hintsUsed` 归零，`status = 'playing'`。
  - `status` 为 `won` / `failed` 时，除 `restart` 外所有动作无效。
  - `autoCandidates` 为真时，`notes` 初始化为 `candidates(values)`。
